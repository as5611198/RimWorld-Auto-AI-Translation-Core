# API 網址與選用密鑰

自訂 OpenAI 相容服務使用 `Custom_OpenAI`。填寫服務提供的完整 `http://` 或 `https://` 網址和模型 ID；如果服務不要求密鑰，密鑰欄可以留空。需要驗證的服務仍須填有效密鑰，模組不會替服務省略驗證。

例如 Base URL 是 `http://127.0.0.1:4315`：

- 自訂 OpenAI 相容網址若沒有 `/v1`，模組會先嘗試 `GET http://127.0.0.1:4315/v1/models`。
- 若模型清單回傳 404，模組會自動改試 `GET http://127.0.0.1:4315/models`，並在本次執行中沿用成功的路徑。
- 實際翻譯／測試連線會使用成功協商出的 Base URL，再接 `/chat/completions`。
- Player2 模式會使用可編輯的自訂網址；輸入 `http://127.0.0.1:49152` 時會自動試 `/v1`，因此不依賴固定的 4315 埠號。
- Player2 模式另外填 Player2 開發者後台取得的 Game Client ID；API 密鑰欄可留空。這個 ID 不是玩家密鑰，也不會由模組猜測或共用其他模組的 ID。
- 提供完整 `/models` 或 `/chat/completions` 位址時，模組會先去掉該尾段，再組合對應接口。
- 服務沒有模型清單接口時，可以手填模型 ID，再測試連線；模型清單失敗不等於翻譯失敗。

這是通用 OpenAI 相容接口的設定說明，未代表已完成 Player2 帳號、授權與實際翻譯驗收。

## 修正內容

- 自訂 OpenAI 相容網址預設先補 `/v1`；模型清單收到 404 時自動退回未加 `/v1` 的網址，並沿用成功路徑。
- 移除「把任意輸入補成 http:// 網址」的處理；既有省略協定的自訂網址須補上 `http://` 或 `https://`。
- 在設定畫面與送出前檢查網址，攔截密鑰誤貼、非 HTTP(S)、登入資訊、查詢參數、片段及內部空白。錯誤訊息不包含輸入值。
- 翻譯池、測試連線、模型清單和 Policy Agent 共用密鑰／網址檢查。`Custom_OpenAI` 有有效網址時允許空密鑰；其他供應商仍要求密鑰。
- 空密鑰不會產生 Authorization 標頭；有密鑰時沿用既有 Bearer／供應商驗證。
- 模型清單派發逾時日誌不再輸出網址，避免再次把誤填的密鑰寫進日誌。
- 設定欄位 `Key` 和 `CustomBaseUrl` 分開序列化；未發現互相覆蓋，這次不自動搬移或改寫玩家的設定。

## 驗證

設定頁的「測試連線」會保留本次結果。失敗時只在左上角顯示一則通知，包含 HTTP 狀態碼（有收到時）、中文或目前語言的原因說明，以及服務端錯誤摘要；沒有服務端訊息時顯示底層連線錯誤。摘要會合併換行並限制長度，避免佔滿畫面。診斷視窗不會自動開啟；可在設定頁手動查看或複製包含實際請求網址（不含查詢參數）、模型及詳細錯誤的資訊，不需要開啟開發者模式。完整診斷仍寫入模組日誌，但不再另外彈出整份日誌通知。翻譯 API 與 Policy Agent 設定共用這個介面。

診斷會遮蔽本次設定的金鑰、Player2 ID，以及回覆中的常見密鑰欄位與 Bearer Token；不會複製完整請求、驗證標頭、任意 JSON 回應欄位或 HTML 錯誤頁。測試結果只保留於本次遊戲執行，變更網址、金鑰、協定或模型後不會繼續顯示舊結果。測試成功表示 API 接受了請求，不代表已驗收實際翻譯品質。

`x-api-key` 是另一種 HTTP 驗證標頭，其值通常為服務提供的 API 金鑰。它與 Anthropic Messages 請求格式是兩件事；額外加入此標頭不等於實作 Messages 協定。目前一般 OpenAI 相容服務仍使用 `Authorization: Bearer`，本次診斷介面變更未調整驗證方式。

`tests/ApiConfigurationSelfTest` 載入實際編譯出的模組 DLL，離線驗證網址正規化、錯誤密鑰欄位、自訂服務空密鑰、模型清單路徑及既有供應商的密鑰要求。所有密鑰都是合成測試資料，不發送網路請求。

```powershell
dotnet build tests/ApiConfigurationSelfTest/ApiConfigurationSelfTest.csproj -c Release
```

執行參數：`<mod.dll> <game assemblies directory> <harmony.dll>`。1.5／1.6 DLL 用 net48 測試程式；1.7 DLL 用 net10.0 測試程式。

本機 1.6 僅有編譯參考程序集，因此其設定測試以 1.5 遊戲依賴解析共用型別，不能視為在 1.6 Unity/Mono 遊戲中的驗收。1.7 測試使用本機 .NET 10 與遊戲 DLL，也不是 Waylith 遊戲內操作驗收。實際 Player2 服務的路徑、授權、HTTP 標頭與翻譯結果仍需端到端測試。

2026-10-20 診斷介面驗證：1.5、1.6、1.7 Release 編譯均通過；各版本 DLL 的 91 項離線 API 檢查通過，涵蓋 HTTP 分類、DNS／逾時錯誤、服務端訊息擷取、金鑰遮蔽、舊測試回呼隔離及設定變更。1.6 DLL 放入僅含模組與 Newtonsoft.Json 的測試目錄，以 1.5 執行依賴解析共用型別，避免直接載入 1.6 編譯參考程序集。九種語言各 17 個新鍵的 XML、鍵集合及 Placeholder 檢查通過；本機模組包的九個編譯產物已核對 SHA-256。尚未進行遊戲內視窗／剪貼簿操作或 Agnes 帶金鑰實連驗證，未部署 Steam 安裝目錄或發布工坊。

同日晚間依使用者測試回饋取消失敗時自動開啟診斷視窗，並避免完整診斷日誌再產生第二則通知。通知優先顯示已遮蔽的服務端原因，沒有時顯示底層連線錯誤；摘要合併空白、限制為 180 字元加省略號，保留 Unicode 字元邊界。三版本重新編譯通過，1.5 與本機已安裝 1.7 DLL 各通過 96 項離線檢查，包含新增的摘要、DNS、長訊息、Unicode 及成功回應內容隔離檢查。九種語言 XML 與鍵集合通過，已部署本機 Steam 模組並保留繁中覆寫；新版通知畫面尚未遊戲內驗收。使用者回報 Agnes 中國站與國際站各自配對金鑰／網址均可使用，中國站金鑰配國際站網址失敗；這是使用者的實連結果，未因此判定原玩家的具體錯誤原因。
