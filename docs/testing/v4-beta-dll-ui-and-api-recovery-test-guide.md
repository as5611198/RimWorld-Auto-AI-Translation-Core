# V4 Beta：DLL UI 翻译、统一工作台与 API 恢复测试说明

## 1. Agent 与 DLL UI 翻译是什么关系

它们属于同一条自动翻译流程，但不是同一个步骤：

1. DLL 扫描器只读检查已启用且程序集已经加载的 Mod，召回可能含有玩家可见文本的字符串。
2. 本地静态分析根据调用路径给出“需要翻译 / 不需要翻译 / 不确定”三态结论。
3. 云端判断缓存仅在来源指纹和规则版本完全一致时复用既有判断；服务端不可用时自动跳过。
4. Agent 预判只处理本地仍然“不确定”的项目，不生成译文。
5. 普通翻译 API 只为最终判定“需要翻译”的项目生成译文。
6. 定向运行时补丁只替换清单中身份与指纹仍匹配的字符串，不改写第三方 DLL。

可以把 Agent 预判理解为自动流水线中的可选判断步骤。没有配置可用模型时，本地规则仍能运行；确定项目照常处理，不确定项目保留原文并等待人工处理。

## 2. 开关位置与模型来源

打开“AI 智能汉化网络 → 详细系统与 API 设置”：

- “启用 DLL 硬编码 UI 扫描与定向翻译”决定正式翻译范围是仅 XML，还是 XML+DLL；
- “启用 Agent 预判”决定是否把本地不确定项交给模型；
- “云端判断缓存”可以独立于 Agent 预判开启；
- “旧版动态 UI 硬编码拦截”是兼容/研发功能，与定向 DLL 翻译互斥。

Agent 预判没有独立 API 配置。它使用共享三级模型池，优先选择 Standard，随后回退到 Precision、Bulk；真正生成译文仍由普通批量翻译路由完成。DeepL 不参与 Agent 预判。

## 3. 推荐的一键使用方法

1. 启用待测试 Mod 和 `AI 智能漢化網絡 V4 DEV`，然后重启游戏，使目标 DLL 实际加载。
2. 在详细设置中开启 DLL 扫描；按需开启云端判断缓存和 Agent 预判。
3. 回到终端控制台，点击“智能补翻”。
4. 可先点“本地规则试跑”查看结果；试跑不会调用 Agent，也不会写入翻译。
5. 点击“开始翻译”。程序会自动补跑已启用但尚未完成的判断步骤，不要求逐个 Mod 手动扫描。
6. 翻译完成后关闭并重新打开目标 Mod 窗口；启动期界面需要重启游戏验证。

模组选择窗口中的“仅选未翻译 Mod”默认排除官方本体和 DLC，但用户仍可手动选中官方内容。未启用但具有 XML 来源的 Mod 仍会显示，并提示“XML 可分析；启用并重启游戏后才能分析 DLL”。试跑完成后可从总结果入口查看全部 Mod，也可直接点击对应 Mod 行右侧的“查看详情”；DLL 摘要应包含分析器版本。“0 个候选”只表示当前分析器没有召回候选，不能据此断言 DLL 内没有玩家可见文本。

DLL 静态不确定项按“本地规则 → `dll` 域云端判断缓存 → Agent 预判”处理；云端 404、超时、坏 JSON 或错误 Schema 均降级继续。当前公共服务尚未部署域感知写入契约，因此 DLL 判断只读查询已接通、普通客户端上传仍被硬禁用。

## 4. 全域编辑器与人工纠错

全域编辑器左侧来源树为“全部 / XML / DLL”：

- XML 下按原有 Def/Keyed 分类展开；
- DLL 下按程序集展开；
- 搜索只作用于当前来源节点和分类；
- DLL 节点不会显示 XML 导入、导出等不适用操作；
- DLL 条目可以设为“需要翻译 / 不需要翻译 / 恢复自动判断”，人工决定优先于重新扫描和 Agent；
- 手填 DLL 译文或对其执行翻译时，会自动设为“需要翻译”。

“一键翻译当前范围”处理当前来源、分类和搜索条件共同筛选出的全部结果，不只是当前滚动视口。它默认跳过已有有效译文，分批请求，不自动保存；中途停止时已经完成的译文仍以未保存状态保留。

## 5. HTTP 429、排队、超时与停止

- 正常排队不算 API 超时；只有请求真正发出后才开始响应计时。
- 普通翻译、连接测试和获取模型列表采用同一条原则；主线程繁忙时连接测试与模型获取继续排队，不应在发送前报超时，连接测试也不得中止无关请求。
- 云端判断缓存同样在真正发送后才计算响应超时；停止时，尚未发送的缓存查询不得在稍后从主线程队列中“复活”。
- 前一个请求失败仍会释放并发名额，后续排队请求继续发送。
- 普通译文、Agent 预判和术语 Agent 遇到明确的 HTTP 429 且不是余额/配额错误时，程序降低有效并发并按 3/8/20 秒最多恢复三次；停止或跳过当前 Mod 可中断等待，首次成功后按 1、约二分之一、约四分之三、配置上限分阶段恢复。
- 三次仍为超并发时，会明确提示服务商并发或频率限制。
- 超时日志写明条目数、源字符数、预计输入 Token、请求阶段、超时值，并标记“无响应”。
- 已收到但格式错误的响应会向普通用户显示最多 320 字符摘要，完整的服务商原始响应写入开发日志，供开发者定位具体字段或格式问题。
- 余额、鉴权、HTTP、格式错误、本地调度异常和用户取消分别归类，不再统一显示成含糊的“API 异常”。
- Policy Agent 与术语 Agent 的非 429 超时、HTTP、配额、传输和格式错误也使用同一套详细分类与同根因聚合，不应只出现 `http_0`、`malformed_response` 等内部代码。

只要主流程、旧 UI 分类/翻译队列、排队请求、活动请求或重试等待任一存在，停止按钮都应可见。点击停止后不得再创建新批次，并应清空旧 UI 未发送项目与 API 排队、中止活动请求、取消恢复锁和递增重试等待。停止期间界面应显示“正在排空请求”及实时计数，重复停止和跳过不可再操作；全部稳定归零后才恢复“开始翻译”，日志出现“翻译已完全停止”。

## 6. 建议验收清单

- [ ] 不配置 Agent 模型时，本地规则试跑可用且名称正确。
- [ ] 未启用但具有 XML 来源的 Mod 仍显示，且明确提示 DLL 需启用并重启；一键 DLL 分析不会处理该 Mod。
- [ ] 开启 DLL 后，“开始翻译”自动处理所有所选且已加载的 Mod，不要求逐个扫描。
- [ ] 试跑完成后窗口不关闭，总结果入口和每 Mod 行“查看详情”均可打开；DLL 摘要包含分析器版本。
- [ ] DLL 扫描结果为 0 候选时显示“当前分析器未识别到候选”，不宣称 DLL 没有玩家可见文本。
- [ ] 云端关闭/Agent 关闭、仅云端、仅 Agent、二者同时开启四种组合行为符合说明。
- [ ] 人工覆盖在重扫后仍保留；恢复自动判断后重新采用自动结论。
- [ ] 全域编辑器“全部 / XML / DLL”树、分类与搜索范围同步。
- [ ] 当前范围批量翻译跳过已有译文、可停止、不自动保存。
- [ ] 1366×768、100% UI 缩放下核心按钮和两个日志框可用；更小空间才出现外层滚动。
- [ ] 正常排队超过 5 秒不会误报失败，超时从实际发送后计算。
- [ ] 普通译文、Agent 预判和术语 Agent 的 429 降并发与三次递增等待均生效；余额类错误不会误入超并发恢复，停止/跳过可中断等待。
- [ ] Agent 预判和术语 Agent 分别制造一次响应超时及一次 HTTP 200 格式错误：超时项显示输入摘要与“无响应”，格式错误显示真实响应摘要，开发日志保留完整响应，且同根因批次被聚合。
- [ ] 翻译运行、排队或重试期间停止按钮始终可见；停止后各计数归零。
- [ ] 在主流程刚完成 API 排空、即将切回空闲的时刻点击停止：旧 UI 队列或活动批次仍须排空，界面不得先恢复空闲，也不得遗漏“翻译已完全停止”。
- [ ] 在普通/结构化/DeepSeek 请求已经成功返回、但用户紧接着点击停止的时序下，本批成功译文仍被解析并写入断点，未返回项不被伪记为 API 故障。
- [ ] 未解决项人工重试在一批中途停止或后续处理抛错时，已接纳条目仍保存并从未解决清单移除；其余条目保持原状态，可继续重试。
- [ ] DLL 自动翻译在内置词典阶段、任意 20 条 LLM 批次后停止或异常时，已完成清单仍保留；部分停止不得显示整轮完成，也不得自动关闭旧版动态拦截开关。
- [ ] MOG 等控制台 Mod 在两种拦截都关闭、仅旧拦截、仅定向 DLL 翻译三种情况下分别验证。
- [ ] 术语总开关关闭时没有术语 Agent 请求；只勾选部分 Mod 时其他 Mod 不贡献语料。
- [ ] 同组系列 Mod 能复用术语，不同组的同名词保持隔离；冲突项可在“审核术语”中批准或拒绝。
- [ ] 云端 404 不弹警告；超时/5xx/坏 JSON 只警告一次并继续 Agent，连续失败后不再逐 Mod 等待。
