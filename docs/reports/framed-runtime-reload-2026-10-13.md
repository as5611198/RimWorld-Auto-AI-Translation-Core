# 译文热重载分帧修改（2026-10-13）

状态：用户已确认实施；源码已修改，仅静态审阅，未经编译或运行验证。

## DLL

- 清单仍在后台读取；校验、显示参数规划、拆卸和安装补丁由现有主线程 pump 驱动，每 Unity 帧最多调度一次，耗时达到约 4 ms 后让出。
- 比较完整方法身份及条目 ID、原文、字面量序号和显示调用签名；译文本身不进入补丁结构签名。结构一致且 Harmony 补丁仍存在的方法保留，仅更新译文快照。
- 删除的或结构变化的方法才拆卸；新增或变化的方法才安装。失败清理、恢复上一份清单也分帧执行。
- 异步完成通知在应用结束后发出。连续请求合并到后续最新清单；不再把“已发出请求”当作热重载完成。空清单清理失败不能报成功。

## XML

- 已成功注入且译文未变的 Def 条目跳过；新增、变化、尚未成功注入以及恢复原生/原文的条目进入本次变更集合。
- 使用游戏公开的 `DefInjectionPackage.InjectIntoDefs` 处理字段路径，每个临时包最多 64 条，引用真实注入对象，保留游戏写回的 injected、replacedString 等状态；不替换游戏的完整语言包字典。
- 保留先尝试、再报告缺失 Def 的两轮处理。第二轮只处理第一轮未成功的条目；错误回传，不能假报全部应用成功。
- 清理旧条目、注入、临时恢复项清理、派生标签规范化均让出主线程。Keyed 和 Def 字典写入保留数量限制，另加约 4 ms 调度预算。
- 原同步 MemoryDrop 兼容入口统一接入后台准备与分帧应用，不再同步读盘、整次注入。
- 当前语言或目标语种变化后不继续把分帧工作应用到另一份语言对象。
- 分帧累计时间仅作调试统计，单帧超时仍单独记录。

## 静态审阅边界

本机 1.6 游戏程序集元数据及 IL 确认：全量语言注入遍历所有 Def 包；包注入跳过 injected 条目，并调用游戏自身字段路径处理和 Def 缓存清理。新的临时小包复用这些行为。`LoadData()` 仍作为前置条件保留，已加载时直接返回。

4 ms 是让出预算，不是抢占式硬上限：一个方法安装、一个 64 条注入小包、首次语言加载、快照复制等单次操作仍可能超过预算。Def 派生标签规范化仍检查全部相关 Def，但逐条分帧。显式重置翻译包后的全量基线恢复是另一个维护入口，本次没有改写其同步恢复逻辑。尚不能据静态审阅断言群友的 30～60 秒卡顿已完全消除。

## 独立 UI 缓存（提案，尚未实施）

建议最多 4096 条，并以估算占用 8 MiB 为第二个淘汰条件，达到任一限制就淘汰近期未使用的项。普通短标签按原文加译文约 200 个 UTF-16 字符估算，字符串内容约 1.6 MiB，加字符串对象、字典和淘汰记录，预计约 2～4 MiB；长说明会更高。8 MiB 是缓存账本估算值，不是进程实际内存硬上限，仍有容器容量、分配器及后台队列开销。

数据库保存全部译文，淘汰缓存不删除数据库。此容量与内存范围仅为方案估算，未通过运行测量；本轮未实施独立 UI 来源或其缓存。
