## 待删：不能可靠裁决翻译是否正确、完整或有效的判断

| 类别 | 当前判断方式与影响 | 建议删除范围 |
|---|---|---|
| 英文残留/漏翻 | TranslationResultLanguagePolicy.HasLikelyEnglishResidual 用正则、常见词、字符比例、空格分词拒绝返回值；误拒绝专名和技术名称 | 移除整个英文残留裁决，以及共用 ShouldAccept 的同类调用，清理无调用辅助方法/统计 |
| 其他文字体系残留 | HasUnexpectedScriptResidual 用假名、韩文、西里尔字符数量及是否出现于原文判定语种错误 | 移除据此拒绝译文的逻辑，不能据字符混用判断翻错 |
| 以字形判“繁简错误” | HasWrongChineseVariant 遇到某种字形便拒绝；不能区分引用、姓名、原样保留文本 | 删除拒绝入口；用户选择的繁简转换是另外一项既有功能，不因删除校验而直接删除转换 |
| 猜“占位翻译” | LooksLikePlaceholderTranslation 将 none、null、translation、未完成等值认作占位；大量问号也据比例认作乱码 | 删除自动无效判断，包括 Sanitization、XML/官方语言读取、候选提取、内置字典中的过滤；这些是普通文字，不是游戏格式占位符 |
| 按上述猜测删除已有译文 | PackMaintenance 扫文件后删除所谓 TODO/占位条目；XmlIO 丢弃被判无效的条目 | 删除依靠猜测过滤或删除译文的步骤，不能只删除 AI 响应校验而留下读回时再次过滤 |
| 判“假语种文件” | IsFakeLanguage 抽样字符并比较繁简数量，XmlIO 可因此忽略整份文件 | 删除整份文件无效裁决；语种依赖语言目录与用户选择等明确元数据 |
| 已保存译文重新接受质量判断 | TryNormalizePersistedGeneratedValue 经 ShouldAccept 再次过滤已保存输出 | 删除读回时的质量裁决，保留单独约定的格式/转换功能 |
| 字符比例推断“已经翻译了” | LooksLikeTargetLanguage 及 IsAlreadyInTargetLanguage；用于 XML 候选、静态字符串刷新、JobReport、配方等；可能把混合句当已翻译或漏译 | 清理将语言猜测当译文状态的入口，改用当前语种译文记录、来源与哈希等明确证据；不能简单去掉 return 后无条件覆盖现有文本 |
| 原文/译文相同即判失败 | TranslationValidation 中未变化检查；也被保护片段缺失后的回退触发 | 不用相同文本推断漏翻；确实漏保护片段时，直接报告漏失的片段，保留结构检查 |
| 配方“补漏”推测 | MemoryInjection 中英文残留、Making 前缀及目标语种猜测共同决定配方文字重写 | 去掉据语言推断译文失效或重写的逻辑；只保留有明确结构规则/译文来源支持的动作 |

上述共用函数覆盖 AI 翻译、人工编辑、同步导入和内置字典等入口，实施时需连同调用者一起清理，避免留下不同入口不同结论。

## 保留：明确的格式和程序契约

- 空响应/空译文检查。
- JSON 是否能解析、items 是否存在、编号是否重复/越界/缺漏、每条是否有结果。这是响应结构契约，不是翻译质量裁决。
- 游戏占位符和格式参数，如 {0}、{1}、约定的受保护片段、grammar 控制变量、标签及前缀的保留检查。
- XML 能否解析、译文键与条目 ID 是否匹配、原文哈希变化检测、当前语种和已有译文来源保护。
- 明确的字段结构、文件路径、资源引用、类型引用、代码数据流等候选分析证据。它们用于判断程序用途，不用于猜测译文质量。缺乏证据时应列为待判定，不设通用技术词黑名单。

“TODO/占位翻译”的字符串猜测与“{0}/游戏占位符”的格式检查是两回事，前者列入待删，后者保留。

## DLL 待判定与 AI 复核错误分开分析

三项原句 harmonypatch:、aboutincompat:、wid: 均来自 DLL 字符串。静态数据流未证明它们被显示，也未证明它们作为技术键使用，当前输出 UNKNOWN_DYNAMIC_FLOW/待判定。保守留待判定符合现有职责，不能说“待判定就错了”；但原 Mod 的源码已证明它们是诊断来源标识/字典查找键，进一步识别该数据流后可以明确判无需翻译。

AI 复核提示词已经明文要求 lookup keys、serialization values、code-only identifiers 无需翻译，因此不是完全缺少这条规则。当前给模型的条目含原文、类名、方法名、定位、发现方式和分析分类，却没有相邻 IL、属性写入/字典操作及最终用途的充分证据。模型理由将它们断言为 UI label，与实际 Source 和 dictionary key 用途不符。

现有证据能确认“复核结论错误”和“输入用途证据不足”。不能仅凭该次结果确定模型能力不足，也不能确定改一句提示词必然修复。应先补充扫描已能取得的用途证据，让无明确界面显示证据的字符串保持待判定，而不是让模型编造用途。无自动模型调用对照结果，本报告不作模型能力排名。
