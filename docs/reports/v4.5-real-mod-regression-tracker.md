## 本轮通用修复边界

- DLL 处理不是按 Mod 名称写特判；改动覆盖所有使用 `LoadFolders.xml` 版本目录、运行时影子复制、构造函数文字、`TaggedString`／`GUIContent`，以及 Unity `GUI.Button`／`GUI.Box` 的 Mod。
- XML 处理不是按 `lantern` 或 `respirator` 写特判；改动覆盖所有冻结规则中明确属于文本的单词字段，同时保留路径与黑名单约束。
- 分析器版本已提升为 `xml-4` 与 `dll-3.06`，旧的漏扫结果应在重新分析时失效；是否达到预期仍需游戏内人工验收。
- Workshop 样本位于 `E:\Program Files\RimWorld\ATC_TestWorkshop`，与 Steam 正式订阅目录隔离。

## 建议验收顺序

1. 先用少量 Mod 验收 Modern Learning Menu、Radius UI、Medieval Lighting and Heat、Fantasy Biotech 的分析数量与实际 UI。

## 新旧版已有译文识别迁移准备（2026-10-06）

本轮称谓约定：当前改过界面和五步工作流逻辑的实现称为“新版”；此前实现统称“旧版”，不再以 V3／V4 版本号代替这个边界。本节是静态调查和迁移准备，未实施迁移。

### 已确认目标

- 用户手动维护参考字典的方案暂定，不加入自动提词、词性分析、学习或词库更新；本次不实施字典或批量替换。
- 相同条目且原文哈希相同的已有译文不自动重翻；原文哈希改变后按新的待翻译内容处理。
- 保留当前条目身份、文本哈希、单条目单语言当前译文记录、任务互斥与后台分页框架，不重新接回旧翻译主流程。

### 旧版逐条补漏实际流程

1. 扫描本地生成包和所有已启用 Mod 的目标语言译文；汉化包使用自己的语言目录扫描入口。读取 Keyed、DefInjected，并保留译文来源。
2. Keyed 按键名查找，DefInjected 按 Def 类型和键路径查找，旧版另有 General 类型回退。Mod 原生与本地译文先形成候选，再按来源策略选择；全局集合使独立汉化包中的译文可以参与目标 Mod 的补漏。
3. 找到可用译文就写入本次结果并跳过 AI；未找到时进入待翻译队列。旧版会对已有译文进行语言、变量与格式检查，拒绝时可能重新排入 AI；这部分与当前“不自动覆盖已有译文”的要求不同，不应照搬。
4. 新翻译与保留的旧译文共同形成输出，记录来源，再触发运行时刷新。旧版的全局裸键匹配和整包删除方式不作为新版迁移目标。

### 新版静态缺口

| 环节 | 当前事实 | 迁移准备 |
|---|---|---|
| 原生目录 | `ModAnalysisTargetFactory` 已读取目标 Mod 的有效语言目录，语言与版本路径工具可复用。 | 保留现有路径解析，不重复开发。 |
| 独立汉化包 | `GetAllTranslationPatchLangPaths(mod)` 实际返回传入 Mod 自身目录内的语言路径。工厂把它与目标自身有效目录合并，未汇总其他已启用 Mod 的译文。此前将其解释为已经读取独立第三方汉化包不准确；`ReadExistingTargetTranslations` 虽能标记根目录外文件为 ThirdParty，但常规工厂没有提供那些外部目录。 | 迁移旧版的外部译文收集能力，并保留提供者、目标范围、原文件与键。 |
| 条目匹配 | 新版按桶、Def 类型、键路径查找，读入字典使用大小写敏感匹配；旧版常用大小写不敏感匹配，且有 General 回退。 | 先检查真实样本的目录、键大小写与类型布局，不直接扩大匹配规则。 |
| 保存记录 | 已有外部译文可写入新版 TranslationResults，每条目每语言更新同一行；没有必要建立第二套译文数据库。 | 复用已有保存接口，补齐真实外部来源包与路径。 |
| 译文有效性 | 新版外部导入也调用译文校验器，拒绝时记录失败；后续是否进入补译须一并审阅。外部文件首次导入没有原文哈希证据，只能按键对应当前候选。 | 区分“确实缺失”和“发现译文但无法采用”，不得把后者静默当缺失后自动改写。具体处理行为仍需确认。 |
| 原文变化 | 现有导入流程遇到保存时原文哈希与当前原文不一致会跳过；同步清理旧绑定与重新导入的顺序仍需完整检查。 | 保留已确认原文哈希规则，检查旧绑定不会永久阻止后续新译文进入。 |

| 运行时显示 | XML 注入与 DLL／旧 UI 缓存是不同链路，仅排除 AI 队列不能保证旧输出不覆盖外部汉化。 | 按条目清理或避让低优先级托管输出，并审阅显示链路；不整包删除其他手工成果。 |

### 拟实施顺序

1. 确认跨 Mod 同名键的借用边界，然后建立带来源的外部目标语言译文集合，避免直接复刻全局字典覆盖。
2. 对当前原文候选匹配已有译文，复用新版记录和来源优先级；已有有效记录继续复用，缺失项才交给 AI。
3. 接通分析复用与翻译前的译文刷新，处理汉化包新增、更新、卸载，不改变五步职责与互斥规则。
4. 衔接托管输出与运行时优先级，防止“数据库已识别汉化但屏幕仍显示旧机翻”。
5. 静态对照全汉化、部分汉化、独立汉化包、Mod 更新、同名键冲突及汉化包卸载路径；功能效果留待用户人工验收，不自行运行测试。

待确认：是否只借用能关联到目标 Mod 的外部汉化，而禁止旧版的跨 Mod 裸键全局借用；发现已有译文但校验拒绝时的用户处理方式。未经确认，不实施这些行为变化。
