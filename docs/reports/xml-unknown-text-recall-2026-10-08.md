# XML 未知文本宽召回

日期：2026-10-08。状态：代码已修改，仅人工静态审阅，未编译或运行。

编号更正：已核对 2026-09-07 发群的 V4.5 测试包，其 XML 规则为 `xml-3`、DLL 规则为 `dll-3.04`。按用户要求，本批未发布的 XML 修复统一编号为 `xml-3.01`；此前实施记录中的 `xml-4` 至 `xml-7` 是开发过程编号，不作为发布版序列继续递增。后续小改动沿用小数编号，不逐项递增整数大版本。既有历史报告与测试记录保留当时编号以便追溯。

## 已确认行为

用户确认：保留明确文本字段规则；未知字段中疑似自然语言的内容收集为待复核，保留路径和原因。明显 ID、引用、资源路径等不走兜底；收集阶段不调用模型。取代旧规则对未知字段不召回的部分，不把未知字段直接标记为需要翻译。

## 实施

- `TranslationPolicyXmlScanner`：流式读取（包括 Def 名称尚未读到的暂存阶段）、XElement 和继承解析使用的 XmlNode 共用 `IsDefLeafCandidate`。先沿用已有规则，再尝试未知自然语言兜底。
- `TranslationPolicyClassifier`：排除已知字段／路径后，结合字段、列表父字段、保护路径和文本形态收集未知文本。排除引用字段、明显结构化标识符、路径、数字／布尔值、纯格式控制等；可见文本至少包含两个字母（包括 Unicode 文字）。纯普通单词仍有语义歧义，因此只进入待复核。
- 分类原因 `unknown_field_natural_language` 对应 `Ambiguous`，工作流映射为 `Undetermined`。已有硬拒绝及目标语种识别仍优先，原生译文查询仍对收集到的候选执行。
- `XmlWorkflowCandidateContext.CollectionReasonCode` 持久化在已有 ContextJson 中，与最终 PolicyReasonCode 分离；不新增数据库表或迁移。即使目标语种检查改变最终分类，也保留收集依据。
- 分析器版本升级为 `xml-3.01`，防止复用 `xml-6` 的完整分析结果；候选稳定 ID、文本哈希及已有译文规则未修改。

## 静态审阅

实现角度：逐项对照三种读取路径，原重复叶子判断统一到同一入口；列表编号、父路径、继承来源、语言文件直接读取方式沿用。移除已无调用的 XElement 列表辅助重载。

业务角度：新增兜底不返回 HardAllow；待复核条目继续通过现有人工分类或用户选择的 AI 复核流程处理。普通单词无法仅靠文本排除引用，因此允许形成待复核记录，但没有增加收集时的 API 调用。既有人工／AI 分类及原生译文判断不因新增兜底失效。

静态推演示例（不是运行结果）：未知字段中的 `Ready`、`Please choose a target` 可以收集为待复核；`SomeDefName`、`some_id`、`resource123`、`Textures/Icon`、`true`、`(1, 2)` 不走新增兜底；`recipeUsers` 列表中的 `Building` 按引用字段排除；纯 `{0}` 没有可见自然语言，不走兜底。已知 `label`、`stuffAdjective`、`rulesStrings` 仍优先沿用已有规则。

## 边界

此规则是候选召回启发式，不承诺识别全部自然语言或消除所有误收。仍只处理既有纯文本叶子；含注释或其他混合节点的叶子未在本次放宽。新增候选数量及扫描耗时没有运行测量，历史 199 项检查不作为本次验证证据。
